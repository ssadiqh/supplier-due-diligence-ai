Overview

Phase 3 implements a deterministic rules engine for supplier due diligence. Rules are business logic that can be evaluated without AI, allowing critical decisions to be made by deterministic algorithms. This keeps the system transparent, auditable, and prevents LLM bias from affecting regulatory decisions.

Key Design Decisions


        
    
            
  • No AI in Phase 3: Rules are purely deterministic, no LLM involvement
    • 
            
  • Evidence tracking: Every rule result stores evidence (why it passed/failed)
    • 
            
  • Pluggable logic: Switch statement in RuleService makes it easy to add new rules
    • 
            
  • Phase-based implementation: Some rules stubbed for future phases (financial, compliance, PEP)
    • 
            
  • Cascade delete: Removing a rule doesn't orphan results - they cascade delete with case
    • 
            
  • Immutable timestamps: evaluatedAt cannot be changed after creation
    • 
        


        
        
Database Schema (V3)


        

            
-- Rules table
CREATE TABLE rules (
    id UUID PRIMARY KEY,
    name VARCHAR(255) NOT NULL UNIQUE,
    description TEXT NOT NULL,
    rule_type VARCHAR(50) NOT NULL,
    severity VARCHAR(50) NOT NULL,
    is_active BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Rule Results table
CREATE TABLE rule_results (
    id UUID PRIMARY KEY,
    case_id UUID NOT NULL REFERENCES cases(id) ON DELETE CASCADE,
    rule_id UUID NOT NULL REFERENCES rules(id),
    passed BOOLEAN NOT NULL,
    details TEXT,
    evidence TEXT,
    evaluated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
