Key Design Decisions:

  • Immutability: executedAt set at construction, updatable=false
  • JSON Storage: Input/output as TEXT columns for flexibility
  • CASCADE DELETE: Deleting case removes all tool results
  • @JsonIgnore: Prevents circular JSON serialization
  • @Data + Lombok: Auto-generates getters/setters/toString

Algorithm Deep Dive: Levenshtein Distance

Fuzzy name matching uses Levenshtein distance to handle variations:

Example: "Acme Corp" vs "Acme Corporation Pty Ltd" Step 1: Normalize "acme corp" vs "acme corporation pty ltd" Step 2: Calculate edit distance - No edits needed for "acme " (5 chars match) - Insert "oration pty ltd" (16 edits) - Total distance: ~16 edits Step 3: Calculate similarity maxLength = 21 characters similarity = 1.0 - (16 / 21) = 0.238... ❌ (Below 80% threshold) BUT: "Contains" check catches this: "acme corporation pty ltd" CONTAINS "acme corp"? NO "acme corp" CONTAINED IN "acme corporation pty ltd"? YES → Special case: 0.95 similarity (matches!) ✓

Matching Logic Priority:

  1. Exact match → 1.0 (100%)
  2. Contains match → 0.95 (95%)
  3. Levenshtein distance → calculated (must be > 80%)
  4. No match → similarity score stored for investigation

Error Handling

Scenario: API Timeout

ABNLookupService.lookupABN("12345678901") → RestTemplate timeout (5 seconds) → Catch RestClientException → Log: "ABN lookup failed for 12345678901: Connection reset" → Throw RuntimeException("Failed to lookup ABN: Connection reset") SupplierVerificationService.verifySupplier() → Catch RuntimeException → Log: "Supplier verification failed for case ... API error" → Save ToolResult(success=false, errorMessage="API error") → Return failed result (no exception bubbles up)

Scenario: Invalid ABN

Input: "123" (not 11 digits) → ABNLookupService validates: !abn.matches("\\d{11}") → Throw RuntimeException("ABN must be 11 digits") → Caught by verifySupplier, saved as failed result

Key Learnings

1. Tool Calling Pattern

Problem: How do agents invoke external services?

Solution: Tool abstraction layer (ABNLookupService) that agents will call in Phases 5-10

Pattern: Tool → Service → Repository → Persistence

2. External API Integration

Timeouts: RestTemplate configured with 5-second limits prevents hanging

Validation: ABN format checked before API call (fail-fast)

Error Resilience: All failures caught, logged, and persisted (no loss of information)

3. Fuzzy Matching

Problem: Exact string matching fails for company name variations

Solution: Levenshtein distance + contains logic

Trade-off: 80% threshold balances false positives vs false negatives

4. Immutable Evidence Trail

Design: ToolResult is write-once, never updated

Benefit: Complete audit trail; agents can't retroactively change findings

Usage: Later phases use evidence to explain decisions to humans

5. Structured JSON for Tool I/O

Input/Output stored as JSON: Future phases (Phase 5+) can parse and reason about tool results

Flexibility: Different tools return different structures; JSON accommodates this

Aspect Phase 3: Deterministic Rules Phase 4: Tool Calling
Input Case data (local) Case data + External API call
Logic Pure business rules (if/else) External service + fuzzy matching
Error Handling Validation errors only Network errors, timeouts, API failures
Evidence Rule name + verdict Tool I/O + name match similarity + verdict
Future Use Rules engine stays deterministic Tools become callable by Phase 5+ agents
