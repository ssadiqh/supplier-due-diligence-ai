1. Architecture Overview

HTTP Request ↓ DocumentEvidenceController (Validate) ↓ DocumentEvidenceAgent (Orchestrate) ├─→ DocumentParser (PDF → Chunks) ├─→ Load Prompt Template ├─→ Call LLM (mock for now) └─→ Build Evidence String ↓ ExtractionResult (Entity) ↓ H2 Database (extraction_results table)
📌 Key Principles:
  • Separation of Concerns: HTTP layer → Orchestration → Parsing → LLM
  • Dependency Injection: DocumentParser is autowired for easy mocking
  • Audit Trail: All extractions persisted with input/output/metadata
  • Error-as-Data: Failures captured as success=false, not thrown
  • LLM-Ready: Mock now, real LLM integration when Spring AI 2.0+ available
