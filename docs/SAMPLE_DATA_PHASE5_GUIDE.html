⚙️ Part 2: Phase 5 Implementation

🎯 What is Phase 5?

Goal: Use LLM to extract structured facts from supplier documents
Input: PDF documents (annual reports, certifications, etc.)
Process: Parse PDF → Chunk text → Call LLM → Extract facts with confidence
Output: Immutable ExtractionResult with facts, evidence, metadata
Why: Automate document review and ground evidence in source documents

📝 Core Components

1. Data Classes

SupplierFact.java – One extracted fact
category: "employees" // Type of fact value: "1,250 employees" // The actual value confidence: 0.95 // Certainty (0.0-1.0) pages: [3, 5] // Where in document reasoning: "Stated in report" // Why we extracted it

SupplierFactsOutput.java – All facts from one document
facts: [...] // Array of SupplierFact summary: "..." // Human-readable summary complete: true // Was document complete?

PageChunk.java – One chunk of text
pageNumber: 1 // Which page (1-indexed) text: "..." // 500-char text chunk startPosition: 0 // Char position in page endPosition: 500 // Char position in page

2. DocumentParser Service

Responsibility: Extract text from PDF and break into manageable chunks

Flow:
  1. Load PDF using Apache PDFBox 3.0
  2. Extract text page-by-page
  3. Split each page into 500-character chunks
  4. Add 50-character overlap between chunks (for context)
  5. Track page numbers for citations
Why chunks? LLMs have context limits; 500 chars is digestible while maintaining context
Why overlap? Information at chunk boundaries doesn't get lost

3. DocumentEvidenceAgent Service

Responsibility: Orchestrate the entire extraction flow

Steps:
  1. Parse Document: Call DocumentParser → get chunks
  2. Build Prompt: Load supplier_extraction_v1.txt template
  3. Call LLM: Send chunks to OpenAI GPT-4 (when Spring AI 2.0+ available)
  4. Parse Response: Extract JSON with facts from LLM output
  5. Build Evidence: Create human-readable summary with confidence
  6. Save Result: Persist ExtractionResult to database
Current State: Mock extraction (returns empty facts) until Spring AI integrated

4. ExtractionResult Entity

Responsibility: Immutable audit record of extraction

Fields:
  • id – UUID primary key
  • caseEntity – Which case (ManyToOne)
  • documentEntity – Which document (ManyToOne)
  • toolName – "DOCUMENT_EXTRACTION"
  • toolType – "EVIDENCE_EXTRACTION"
  • input – JSON: {documentId, documentName, chunkCount}
  • output – JSON: {facts[], summary, complete}
  • success – Boolean (true = extraction succeeded)
  • errorMessage – If failed, why?
  • evidence – Human-readable findings with confidence
  • promptVersion – "v1" (for A/B testing prompts)
  • modelUsed – "gpt-4-turbo" (for tracking model performance)
  • tokensUsed – Token count (for cost tracking)
  • executedAt – Immutable timestamp

5. REST API Endpoints

POST /api/cases/{caseId}/documents/{documentId}/extract-evidence
Request: (no body required) Response: ExtractionResult with facts, evidence, metadata Status: 200 OK (always — errors stored as data)
GET /api/cases/{caseId}/extraction-results
Returns: All extraction results for case (optionally filtered by promptVersion) Status: 200 OK with array
GET /api/cases/{caseId}/extraction-results/success
Returns: Only successful extractions Status: 200 OK with array
GET /api/cases/{caseId}/documents/{documentId}/extraction-results
Returns: All extractions for specific document Status: 200 OK with array

📝 LLM Prompt Template

File: supplier_extraction_v1.txt

Purpose: Tells LLM what facts to extract and how to score confidence

Key Sections:
  • Facts to extract: employees, revenue, locations, certifications, regulatory_status, red_flags, ownership, years_in_business, industry, financial_health
  • Confidence scoring:
    • 1.0 = Explicitly stated
    • 0.85 = Clearly implied
    • 0.70 = Inferred from data
    • 0.50 = Ambiguous (don't report below this)
  • Constraints: No assumptions, no marketing claims, require currency/period, must track page numbers
  • Output format: Structured JSON with facts[], summary, complete flag

🔗 Part 3: How They Work Together

End-to-End Flow

Scenario: User uploads supplier's 2024 annual report PDF

  1. Upload: PDF saved to data/case-documents/{caseId}/report.pdf
  2. Trigger: POST /api/cases/{caseId}/documents/{docId}/extract-evidence
  3. Parse: DocumentParser reads PDF, extracts 50 chunks of text with page numbers
  4. Prompt: DocumentEvidenceAgent loads supplier_extraction_v1.txt
  5. Extract: LLM analyzes chunks, identifies 8 facts (employees, revenue, locations, etc.)
  6. Score: Each fact gets confidence: "1,250 employees" = 0.95 confidence
  7. Ground: Pages cited: [3, 5] (can verify immediately)
  8. Save: ExtractionResult → extraction_results table
  9. Return: HTTP 200 with result (HTTP 200 always, errors stored as data)
  10. Retrieve: GET /api/cases/{caseId}/extraction-results lists all extractions
  11. Use: Facts feed into Phase 6 governance checks and Phase 7+ RAG
